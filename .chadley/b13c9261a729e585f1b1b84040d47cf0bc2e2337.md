This app is a **Commander**-specific life tracker: the `Player` model already carries Commander-only state (`commander`, `commanderCasts`, with tax derived as 2× casts), and the UI surfaces "Tax" prominently. Yet it does not track **commander damage** — the format's signature loss condition: a player who takes 21 combat damage from a *single* opponent's commander loses, regardless of life total.

Because this is tracked *per attacking commander* (not a single aggregate), it can't be inferred from `life`. A player at 30 life can still be dead to commander damage. Today there is no way to record it on this table tracker at all.

### Why the code invites it
`Player` models Commander-specific counters but stops at life/tax:
```ts
export interface Player {
  id: number;
  name: string;
  life: number;
  commander: CommanderCard | null;
  commanderCasts: number;   // <- tax modeled; commander damage not
}
```
The existing `commanderTax(player)` helper and the `PlayerZone` tax stepper show the pattern for a per-player derived/edited counter that a commander-damage matrix would follow.

### Suggested shape
Add a `commanderDamage: Record<number, number>` (attacker seat id → total) to `Player`, defaulted `{}` in `createGame` and validated/defaulted in `parsePlayer`/`parseTurnState` (mirroring how `commanderCasts` is parsed with `Math.max(0, …)`). Surface a compact stepper grid in `ZoneMenu` (one row per opponent), and optionally flag a player as lethal when any entry reaches 21. This is a strictly additive, well-scoped enhancement with the highest gameplay value for the app's core audience.
