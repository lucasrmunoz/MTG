`searchCards` builds a Scryfall query that ANDs one `name:` clause per word in **any order** — the doc explicitly states `"bolt light"` and `"light bolt"` both find Lightning Bolt. Results are then reordered so that "searching a card's full name puts that card first":

```ts
.sort((left, right) =>
  matchRank(left.name, term) - matchRank(right.name, term) ||
  left.name.localeCompare(right.name),
);
```

But `matchRank` compares the search term as a single contiguous string:

```ts
function matchRank(cardName: string, term: string): number {
  const name = cardName.toLowerCase();
  const wanted = term.toLowerCase();
  if (name === wanted) return 0;
  return name.startsWith(wanted) ? 1 : 2;
}
```

If the user types the card's words in a different order than the canonical name (`"bolt lightning"`), neither `name === wanted` nor `name.startsWith(wanted)` holds, so "Lightning Bolt" is ranked tier 2 — tied with every unrelated partial match and then ordered only alphabetically. The exact card the user named is therefore **not** surfaced first, defeating the stated purpose of the ranking. Note the C# `ScryfallClient` mirrors this and shares the bug (`scryfall.ts` comment: "Mirrors ScryfallClient").

**Fix:** rank on per-word containment/coverage (e.g. all query words present, or exact set/whole-name match after tokenizing) rather than a single `startsWith` on the raw term.
