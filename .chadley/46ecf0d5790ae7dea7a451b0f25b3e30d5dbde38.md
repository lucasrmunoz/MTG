`GetArtVersionsAsync` builds an exact-match Scryfall query by string-interpolating the raw `cardName` inside quotes:

```csharp
// src/Mtg.Core/Scryfall/ScryfallClient.cs:148
var query = Uri.EscapeDataString($"!\"{cardName}\"");
```

But the name-search path (`BuildNameQuery`) *deliberately* strips `"` and `\` first, with a comment noting "Scryfall's query parser has no escape sequence for them inside a quoted string." The art path applies no such stripping. A `cardName` containing a `"` (or `\`) produces a malformed query like `!"foo"bar"`, which Scryfall parses as broken → 404 → the code treats it as an empty result (`result?.Data is null → break`) and returns an empty art list with no error.

This is reachable from client input: `GET /api/cards/art?name=` forwards an arbitrary caller-supplied string straight into this query (see `CardEndpoints.GetArtVersionsAsync`, which only null/whitespace-checks). Apply the same quote/backslash stripping used by `BuildNameQuery` so the two query-construction paths are consistent.
