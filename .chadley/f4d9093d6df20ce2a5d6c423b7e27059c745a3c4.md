The player-name field in the zone settings menu writes its raw value straight through to game state with no trimming or non-empty guard:

```tsx
// PlayerZone.tsx:319-325
<input
  type="text"
  value={player.name}
  onChange={(event) => onRename(event.target.value)}
  aria-label="Player name"
  ...
/>
```

and the reducer does no validation either:

```ts
// game.ts:200-202
export function setPlayerName(game: GameState, playerId: number, name: string): GameState {
  return updatePlayer(game, playerId, (player) => ({ ...player, name }));
}
```

If a user clears the field or types only spaces, `player.name` becomes `""` (or whitespace). The name is displayed as the primary zone-selector button:

```tsx
// PlayerZone.tsx:185-194
<button ... onClick={() => setMenuOpen(true)}>
  {player.name}
  {player.commanderCasts > 0 && (
    <span className="text-purple-light"> · Tax {commanderTax(player)}</span>
  )}
</button>
```

An empty name produces a blank pill with no identifying text, making it hard to tell which seat is which — and because the value flows into `GameState`, the blank name is serialized into the saved/persisted game, so it survives reloads.

**Fix:** trim on input and fall back to a default when the trimmed value is empty — e.g. guard in `onChange` (`const v = event.target.value; onRename(v)` but reject-blank on blur) or in `setPlayerName`: `name: name.trim() || player.name` (or a `Player N` default). Compare with `createGame`, which already seeds `name: \`Player ${index + 1}\`` (game.ts:87), giving a natural fallback.
