The handler unconditionally assigns `httpContext.Response.StatusCode = 502` and then writes ProblemDetails, with no `Response.HasStarted` guard. If a `ScryfallException` is thrown after the response has already begun streaming to the client (e.g. during serialization/enrichment of a partially written body), assigning `StatusCode` throws `InvalidOperationException` ("headers have already been sent"). That secondary exception escapes the handler, defeating the intent of translating a Scryfall outage into a clean 502 and yielding an aborted/broken response instead.

**Fix:** add `if (httpContext.Response.HasStarted) return false;` after the type check so the framework can abort the connection rather than throwing while writing headers — the standard defensive pattern for `IExceptionHandler`.
