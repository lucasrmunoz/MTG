A guest that joins at the same instant the host publishes a new state can end up displaying the **previous** board (wrong life totals, wrong active seat) and stay wrong until the host's next publish.

`RunGuestAsync` captures the cached state and adds the connection to the guest list in one atomic step, then sends the welcome messages afterward:

```csharp
var (guestCount, cachedState, hostPresent) = session.AddGuest(connection); // adds to _guests, returns S1
...
if (!await connection.TrySendTextAsync("""{"type":"joined"}""")) { return; }
if (cachedState is not null) {
    await connection.TrySendTextAsync(cachedState);   // sends S1 (older)
}
```

`AddGuest` (GameSession.cs:84-92) appends the connection to `_guests` **before** the guest has sent its captured `cachedState` (S1). The moment it is in `_guests`, a concurrent host `state` frame is a valid broadcast target:

```csharp
case "state" ...:
    session.SetCachedState(outbound);          // S2
    await BroadcastAsync(session, outbound);   // GuestsSnapshot() now includes the new guest
```

`SessionConnection` serialises *individual* sends with `_sendLock`, but not the (`joined`, S1) pair. So the broadcast of S2 can slot in between them, and the wire order becomes: `joined`, `state:S2`, `state:S1`. The guest applies whatever arrives last.

The client offers no protection: `state` frames carry no version/sequence number, and `join`'s router applies every one unconditionally (session.ts:222-232 — `parseGame(...)` then `callbacks.onState(game)`), so S1 wins and the board is shown as of the older snapshot. It self-heals only on the host's *next* publish; between turns (host idle) a guest can act on a stale board for a while.

**Fix direction:** give each `state` broadcast a monotonically increasing sequence number (kept on the `GameSession`, assigned under the same lock as `SetCachedState`) and have the guest ignore any `state` whose sequence is not newer than the last applied; the initial cached-state send carries the sequence it was cached at. Alternatively, send the cached state to the guest *before* adding it to `_guests` and replay any state that arrives during that window.
