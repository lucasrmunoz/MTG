The `/api/cards/search` and `/api/cards/art` endpoints validate only that `name` is non-blank. `BuildNameQuery` then splits the term on whitespace and emits one `name:"<word>"` clause per token, joined into a single Scryfall query. An anonymous caller can therefore submit an arbitrarily long `name` (thousands of words) and force the API to build and URL-encode a huge outbound query string against Scryfall on every request — an unbounded-input amplification vector. Scryfall will likely reject an oversized query, which surfaces as a `ScryfallException` → 502/500 rather than a clean client error.

**Suggestion:** add a simple guard (max length and/or max word count) that returns 400 for oversized `name` values, consistent with the existing `MissingName()` 400 path. Low severity because it requires a deliberately abusive input, but the endpoint currently performs no size validation at all.
