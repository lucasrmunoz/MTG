The `due` flag on a reminder is only ever *set* to `true` — nothing in the module ever sets it back to `false` (the only other exit is `dismissReminder`, which removes the reminder entirely). Because `setActivePlayer` is exposed as a *correction* control, this creates a stuck-state bug:

- User taps a seat by mistake in the "whose turn is it" menu → `setActivePlayer` marks that seat's reminders `due: true`.
- User corrects back to the right seat → `setActivePlayer` only ORs `due: true` onto the newly-chosen seat; it never clears the `due` it wrongly set on the mis-tapped seat.

Result: the mis-tapped seat's reminders stay lit ("tap when done") permanently even though it is not that seat's turn. The same one-directional logic in `endTurn` (line 116-121) means an un-dismissed due reminder also carries `due: true` into every subsequent turn cycle.

**Fix:** When moving the active marker, compute `due: reminder.playerId === playerId` (true for the new active seat, false otherwise) instead of only OR-ing `true` onto the target — and clear the outgoing seat's non-end-step reminders in `endTurn`.
