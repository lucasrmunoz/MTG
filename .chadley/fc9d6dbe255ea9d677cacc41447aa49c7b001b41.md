`GetPricesAsync` splits the printing ids into 100-id chunks and calls `PriceFeedHttp.GetCatalogueAsync` per chunk inside a plain `foreach`, accumulating into a single `prices` dictionary:

```csharp
foreach (var chunk in accepted.Chunk(MaxIdsPerRequest))
{
    var response = await PriceFeedHttp.GetCatalogueAsync<Response>(
        httpClient, $"{Path}?{query}", DisplayName, cancellationToken);
    ...
}
```

`GetCatalogueAsync` throws `PriceFeedException` on any HTTP failure, timeout, non-2xx, or parse error. Because the loop has no per-chunk try/catch, a failure on *any* chunk unwinds the whole method and throws away the prices already collected from earlier chunks. The caller `CardPricingService.FetchLiveAsync` then catches the exception and drops **all** Mana Pool prices for that lookup, returning an empty dictionary.

This matters most on the `/api/cards/art` path, where a popular card can have 100+ printings and therefore several chunks: a single transient 500/timeout on the last chunk silently blanks Mana Pool prices for every printing in the response. The code already goes to great lengths (`IsAcceptableId`, `Distinct`) to stop one bad id from failing the whole batch — the same 'one failure loses everything' problem re-appears across chunks.

Fix: wrap each chunk's request in a try/catch (mirroring the per-vendor tolerance in `FetchLiveAsync`), log the failed chunk, and return whatever prices the successful chunks produced instead of propagating.
