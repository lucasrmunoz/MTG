For transform / modal double-faced / split / adventure cards, Scryfall puts `power`, `toughness`, and `mana_cost` only on `card_faces`; the top-level `power`/`toughness` are `null`. Both mappers correctly carry the face data through — `ScryfallCardMapper.ToFace` (`src/Mtg.Core/Scryfall/ScryfallCardMapper.cs:84-93`) and `toFace` (`src/frontend/src/lib/sources/scryfall.ts:136-146`) both populate `CardFace.power`, `toughness`, and `manaCost`.

But the consumer drops all of it. `powerToughness(card)` (`src/frontend/src/lib/cards.ts:13-18`) reads only the top-level `card.power`/`card.toughness`, so it returns `null` for every double-faced creature, and `CardDetail` renders the Power/Toughness row only when `pt !== null` (`CardDetail.tsx:35,69`). Worse, the per-face rendering block (`CardDetail.tsx:79-93`) prints only `face.name`, `primaryType(face.typeLine)`, and `face.oracleText` — never the face's `power`/`toughness` or `manaCost`.

Net effect: a card like Delver of Secrets or any MDFC/adventure creature shows a Power/Toughness of nothing at all, and the back/adventure face's mana cost is hidden, even though every one of those values was fetched and typed. This affects both API mode and the browser-direct GitHub Pages mode.

**Fix sketch:** in the faces block, render `face.manaCost` (when non-empty) and a `face.power`/`face.toughness` line (when both non-null), or have `powerToughness` fall back to the first face that carries P/T.
