`applyArPlayers` merges life and commander-cast values returned from the native AR bridge, matched by player id. Unlike `parseGame` — which explicitly rejects non-finite `life`/`commanderCasts` on restored saves — this merge path trusts the numeric fields without any finiteness check.

`Math.trunc(NaN)` is `NaN`, `Math.trunc(Infinity)` is `Infinity`, and `Math.max(0, NaN)` is `NaN`. If a malformed native AR result carries `life: null`/`undefined`/`"40"`/`NaN` for a player id the game *does* know, the bad value is written straight into a legitimate player's `life`/`commanderCasts`.

That state then serializes with `JSON.stringify(NaN) === "null"`, so on the next save/reload `parseGame` sees a `null` life, fails to parse, and silently discards the entire game. The function's own docstring claims "a stale or malformed AR result can never corrupt the game," which this gap directly violates.

This is distinct from the already-known items: the missing-`players`-array crash (different failure) and the `parseGame` non-finite guard (a different code path). A `Number.isFinite` guard here — falling back to the existing value when the update is non-finite — restores the documented safety guarantee.
