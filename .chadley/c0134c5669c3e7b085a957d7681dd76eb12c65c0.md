`ScryfallCardMapper.ParsePrice` parses with `NumberStyles.Number` (which allows a leading sign) and applies no positivity guard:

```csharp
private static decimal? ParsePrice(string? value) =>
    decimal.TryParse(value, NumberStyles.Number, CultureInfo.InvariantCulture, out var parsed)
        ? parsed
        : null;
```

Every other price parser in the codebase filters non-positive values — `CardKingdomFeed.ParsePrice` requires `&& parsed > 0` and `ManaPoolLiveSource.ToDollars` requires `cents is > 0`. A `"0.00"` or `"-1"` from Scryfall's `usd`/`usd_foil` would therefore make `VendorPrice.IsEmpty` false and be surfaced as a real $0.00/negative TCGplayer price. The frontend mirror `src/frontend/src/lib/sources/scryfall.ts` `parsePrice` has the same gap (`Number.parseFloat("-3")` / `"12.5abc"` pass the `Number.isFinite` check).

**Fix:** add a `parsed > 0` guard to match the other feeds (and the same to the TS mirror).
