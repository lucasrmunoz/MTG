The cache shape guard uses `typeof`:

```ts
const cache = JSON.parse(contents) as CacheFile;
if (typeof cache.fetchedAt !== "string" || typeof cache.prices !== "object") {  // line 245
  throw new Error("The cache file does not have the expected shape.");
}
catalogue = new Map(Object.entries(cache.prices));
```

`typeof [] === "object"`, so a cache with `prices: []` (or any unexpected object shape) passes the check. `Object.entries([])` yields `[]`, `catalogue` becomes an empty-but-non-null `Map`, and `loadFromDisk` returns `true`. `isLoaded()` then reports loaded, and if `fetchedAt` is recent `ensureLoaded` treats the empty catalogue as valid and never re-downloads until the 24h TTL expires — the vendor appears loaded with zero prices. This is distinct from the known "invalid `fetchedAt` treated as permanently fresh" item; here the defect is the `prices` payload shape. (`prices: null` self-heals, since `Object.entries(null)` throws into the catch.)

**Fix direction:** Validate `cache.prices` is a plain object (reject arrays/null), or treat a cache that parses to zero entries as a miss so a fresh download runs.
