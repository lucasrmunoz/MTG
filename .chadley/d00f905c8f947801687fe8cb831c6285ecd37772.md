In `useWakeLock`, every `visibilitychange` to "visible" calls `acquire()`, which unconditionally assigns `sentinel = lock`. If a previous sentinel is still held, its reference is overwritten and that lock is never explicitly released — cleanup releases only the last `sentinel`. The browser auto-releases screen wake locks on `hidden`, but some Android WebViews are inconsistent about firing that, and two overlapping `acquire()` calls (visible→hidden→visible while the first `await request` is still pending) can both resolve and both assign, leaking the earlier lock.

Best-effort feature, so severity is low, but it can hold more screen wake locks than intended on some embedded WebViews. Releasing (or short-circuiting when `sentinel !== null`) before requesting a new lock fixes it.
