After the read loop ends normally (`done === true`), `download` flushes the scanner once more and then only checks that *some* prices were parsed:

```ts
for (const rowText of scanner.push(decoder.decode())) {  // line 203
  addRow(rowText, prices);
}
if (prices.size === 0) {                                  // line 207
  throw new ApiError("...held no usable prices.", 0);
}
catalogue = prices;
fetchedAt = new Date().toISOString();
```

`RowScanner` only emits a row when it sees the closing `}` that returns `depth` to 1. If the document is truncated mid-object (a CDN/proxy closing the connection at a byte boundary that still reports `done` rather than a read error), the final partial object has `objectStart !== -1` and is simply retained in `buffer`, never emitted, and no error is raised. Because `reader.read()` returned `done` cleanly, the interrupted-download `catch` at line 198 does not fire. As long as earlier rows parsed (`prices.size > 0`), the truncated catalogue is accepted as complete, written to disk, and served as fresh for the full 24h `MAX_AGE_MS` — cards in the lost tail show no Card Kingdom price with no signal anything went wrong.

**Fix direction:** After the final flush, assert the scanner returned to root depth (`depth === 0`, not `inString`, `objectStart === -1`); if not, throw the interrupted/malformed `ApiError` so the previous catalogue is kept instead of caching a truncated one.
