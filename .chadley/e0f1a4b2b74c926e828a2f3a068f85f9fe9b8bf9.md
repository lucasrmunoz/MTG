Reminder text is trimmed and rejected when empty, but player names are not — `setPlayerName` stores the raw string and the session validator only bounds its length:

```ts
// game.ts — stores verbatim, no trim / no fallback
export function setPlayerName(game, playerId, name) {
  return updatePlayer(game, playerId, (player) => ({ ...player, name }));
}

// addReminder — trims, for contrast
{ id, playerId, phase, text: text.trim(), due: false }

// sessionActions.ts — rename validation: length only, empty/whitespace allowed
case "rename":
  return isSeatId(value.playerId) &&
    typeof value.name === "string" &&
    value.name.length <= MAX_NAME_LENGTH   // "" and "   " pass
    ? { kind: "rename", playerId: value.playerId, name: value.name }
    : null;
```

The rename input binds directly to `player.name`, so the local host can clear its own name to blank, and a guest can send `{kind:"rename", name:""}` (or whitespace-only). The result is an unlabeled seat across the life tracker, board view, and AR badges, with no way for other players to tell whose seat it is. This is distinct from the known blank-reminder issue — it is a separate field and code path with no empty guard at all.

**Fix:** fall back to a default (e.g. `Player {seat}`) when the trimmed name is empty in `setPlayerName`, and reject empty/whitespace-only names in the `rename` validator, mirroring the reminder trimming already in `addReminder`.
