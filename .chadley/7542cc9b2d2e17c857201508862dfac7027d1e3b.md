The create path trims reminder text, but the restore path does not, and `reminderLabel` only special-cases the exact empty string:

```ts
// addReminder — trims:
{ id, playerId, phase, text: text.trim(), due: false }

// parseReminder — stores verbatim:
return { id, playerId, phase, text, due };

// reminderLabel — only "" is treated as note-less:
return reminder.text === "" ? phase : `${phase}: ${reminder.text}`;
```

A restored save whose reminder `text` is whitespace-only (e.g. `"   "`) fails the `=== ""` check, so the chip renders as `"End step:    "` — a phase label with a dangling colon and a blank note, instead of the clean `"End step"` the create path guarantees. The inconsistency is that `parseReminder` accepts untrimmed text while `addReminder` normalizes it. Trim in `parseReminder` (or compare `reminder.text.trim() === ""` in `reminderLabel`) so restored and freshly-added reminders label identically.
