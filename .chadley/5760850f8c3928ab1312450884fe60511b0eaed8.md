## What
The startup vendor effect in `Home` polls `fetchVendors()` every `VENDOR_POLL_MS` (10s) and is designed to **stop once every vendor reports `loaded`**:

```tsx
// page.tsx:55-88
async function loadVendors() {
  let list: VendorInfo[];
  try { list = await fetchVendors(); } catch { return; }
  if (cancelled) return;
  setVendors(list);
  setVendorId((current) => (current === "" ? (list[0]?.id ?? "") : current));
  if (list.some((vendor) => !vendor.loaded)) {
    timer = setTimeout(() => void loadVendors(), VENDOR_POLL_MS);  // reschedules while ANY vendor is unloaded
  }
}
```

The comment on this block (lines 53-54) states the premise: *"its catalogue is downloaded in the background and its prices appear shortly after startup. Poll until it reports loaded, then stop."* That premise holds in **API mode** (the server downloads Card Kingdom in the background at boot, so `loaded` flips true and the poll stops).

It does **not** hold in the **Android app build**. There, `fetchVendors` comes from `nativeApp.ts`, which reports Card Kingdom's `loaded` from `cardKingdom.isLoaded()`:

```ts
// nativeApp.ts:89-95
{ id: CARD_KINGDOM, name: "Card Kingdom", priceBasis: "NM", live: false,
  fetchedAt: cardKingdom.getFetchedAt(), loaded: cardKingdom.isLoaded() }
```

Card Kingdom's 66 MB catalogue is downloaded **on demand — only when the user selects that vendor** (see `nativeApp.ensureVendorLoaded` / the on-select effect at page.tsx:106-145, and the module doc: *"never at startup, so the 66 MB download never runs unasked"*). So for any user who never opens the Card Kingdom vendor, `isLoaded()` stays `false` indefinitely, `list.some(v => !v.loaded)` stays `true`, and the `setTimeout` reschedules **forever**.

## Impact
- A perpetual 10-second timer runs for the entire lifetime of the mounted page on mobile — never terminating for the common case (user never touches Card Kingdom). This is exactly the case the code's own comment says should stop.
- Each tick calls `setVendors(list)` with a **fresh array of fresh objects**, so React re-renders `Home` and its children (two `PriceControls`, results, art grid, preview) every 10s indefinitely — pure wasted work / battery on a mobile device.
- Because the on-select vendor-load effect at page.tsx:106 lists `vendors` in its dependency array, every 10s tick's `setVendors` also re-runs that effect. When Card Kingdom *is* selected but still downloading, that means `cachedVendors.ensure(vendorId)` is re-invoked every 10s during the download (only saved from duplicate 66 MB fetches by cardKingdom's single-flight guard).

## Fix sketch
Stop polling for vendors that are cached/on-demand rather than background-loaded — e.g. only reschedule while a **live-but-not-yet-loaded or currently-selected cached** vendor is pending, not for any unloaded vendor. In the app build the poll's premise (background load) does not apply to Card Kingdom at all, so it should not keep the timer alive.
