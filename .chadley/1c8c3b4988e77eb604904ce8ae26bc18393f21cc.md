`handleViewInAr` builds the AR reference-image set from `artVersions`. The doc comment above it promises "Every art version rides along as a reference image, so whichever printing is physically on the table is recognised."

But art versions load asynchronously after a card is selected, while the "View in AR" button is rendered and enabled as soon as `cardAr !== null && card.imageUrl !== null` — there is **no `loadingArt` guard** on the button (line 429). When a single search match auto-opens, or the user simply taps quickly, `artVersions` is still `[]`, so `printings: []` is sent. The native layer then has only the single opened printing (`cardId`/`imageUrl`) to recognise and cannot match any of the other physical printings on the table — the entire purpose of shipping reference images.

The primary printing still works, so severity is low, but the multi-printing recognition feature is silently defeated by timing. A `disabled={loadingArt}` (or awaiting the art load before opening) fixes it.
