The card-lookup page's "View in AR" button invokes `handleViewInAr`, which awaits `cardAr.open(...)` but keeps no busy state and never disables the button:

```tsx
async function handleViewInAr() {
  if (cardAr === null || card === null || card.imageUrl === null) return;
  try {
    await cardAr.open({ ... });
  } catch (err) { setError(...); }
}
// button:
<button type="button" onClick={() => void handleViewInAr()} ...>View in AR</button>
```

The button has no `disabled` binding, so repeated taps (or a slow bridge) fire multiple concurrent `cardAr.open` calls into the native plugin.

This is inconsistent with the game page, which added exactly this guard for its AR entry point:

```tsx
// src/frontend/src/app/game/page.tsx
const [arBusy, setArBusy] = useState(false);
async function handleOpenAr() {
  if (cardAr === null || game === null || arBusy) return;
  setArBusy(true); ... finally { setArBusy(false); }
}
<button ... disabled={arBusy}>{arBusy ? "In AR…" : "View in AR"}</button>
```

Fix: mirror the game page — add an `arBusy` state, early-return when busy, and disable the button while the bridge call is in flight.
