The per-device `dismissedSpotlightId` is never reset, but spotlight ids restart at 1 for every fresh game, so a stale dismissal can swallow a legitimate new call-out.

```tsx
const [dismissedSpotlightId, setDismissedSpotlightId] = useState(0); // only ever advanced via onDismiss
...
if (spotlight === null || spotlight.id === dismissedId) {  // exact-match suppression
  return null;
}
```

Spotlight ids are minted per game and reset on a new game:

```ts
// game.ts
spotlight: null,                                   // createGame
spotlight: { id: (game.spotlight?.id ?? 0) + 1, ... } // setSpotlight — restarts at 1 each game
```

The component is not remounted between games, so `dismissedSpotlightId` carries its last value forward. If a player dismissed, say, the 2nd call-out of the previous game (`dismissedSpotlightId === 2`), then in the next game the call-out that happens to be minted with `id === 2` matches `spotlight.id === dismissedId` and is auto-hidden — it never appears on that device, even though nobody dismissed it. The same applies to a guest who leaves one host session and joins another (whose ids also start at 1) on the same mounted page.

**Fix:** reset `setDismissedSpotlightId(0)` when a new game starts (`handleNewGame`) and when a guest leaves/joins, or seed spotlight ids so they never repeat across games.
