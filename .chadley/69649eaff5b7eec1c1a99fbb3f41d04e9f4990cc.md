The "View in AR" button renders only when `card.imageUrl !== null`, and `handleViewInAr` early-returns when `card.imageUrl === null`. But the AR call itself already floats `selectedArtUrl ?? card.imageUrl` for the image and passes every `artVersions` entry as a reference printing. So when a card's *default* printing is the rare imageless one (`card.imageUrl === null`) yet the user has selected an art version that **does** have an image, AR is completely unavailable — the button never appears — despite a perfectly valid `selectedArtUrl` and reference printings to open.

**Fix:** gate both the button render and the handler guard on the effective image `(selectedArtUrl ?? card.imageUrl) !== null` rather than on `card.imageUrl` alone, and pass that effective URL to `cardAr.open`. The bridge already requires only a non-null `imageUrl`, which the selected art satisfies.
