The −1/+1 life targets are real `<button>` elements (hence focusable), but their only handlers are pointer events:

```tsx
<button
  type="button"
  aria-label={`${player.name}: subtract life`}
  onPointerDown={() => startHold(-1)}
  onPointerUp={endHold}
  onPointerLeave={endHold}
  onPointerCancel={endHold}
  className="absolute inset-y-0 left-0 z-10 w-1/2 cursor-pointer touch-none"
/>
```

There is no `onClick` (or key handler). A keyboard user who tabs to the button and presses Enter/Space fires the button's default `click`, which is unbound — so no `startHold`/`endHold` runs and the life total never changes. Keyboard users cannot adjust life at all.

This is distinct from the already-known aria-live/feedback gap for this area (that one is about screen readers not *hearing* a change); this is the more fundamental inability to *make* the change without a pointer. Fix: add an `onClick` that applies a single ±1 (independent of the hold-to-repeat pointer flow), or handle Enter/Space explicitly.
