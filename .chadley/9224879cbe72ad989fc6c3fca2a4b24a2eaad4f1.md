`refresh()` is documented to "download the catalogue again right now," but it piggybacks on any in-flight promise — including an `ensureLoaded` run that resolves after only a disk read, never touching the network:

```ts
export function refresh(): Promise<void> {
  if (inFlight !== null) {
    return inFlight;          // may be an ensureLoaded that short-circuits
  }
  inFlight = download().finally(() => { inFlight = null; });
  return inFlight;
}

export function ensureLoaded(): Promise<void> {
  ...
  inFlight = (async () => {
    if (catalogue === null) { await loadFromDisk(); }
    if (catalogue !== null && !isStale()) { return; }  // resolves WITHOUT download()
    ...
  })().finally(() => { inFlight = null; });
  return inFlight;
}
```

If the user selects Card Kingdom (kicking off `ensureLoaded`, which loads a still-fresh copy from disk and returns at the `!isStale()` guard) and taps "Refresh" during that window, `refresh()` returns that same promise. `handleRefreshPrices` then reports success and re-stamps prices, but no fresh catalogue was ever fetched — the explicit refresh silently no-ops and the user believes they pulled today's prices.

**Fix:** track download-in-flight separately from load-in-flight, or have `refresh()` await the current `inFlight` and then unconditionally run `download()`.
