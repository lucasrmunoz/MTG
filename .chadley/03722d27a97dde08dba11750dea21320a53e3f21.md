`fetchArtVersions` caps iteration at `MAX_ART_PAGES` (10). Each Scryfall page holds up to 175 art-unique printings, so a heavily reprinted card (a basic land, or a staple like Lightning Bolt with hundreds of art-unique printings) is truncated at the cap and the function returns a silently partial list.

Unlike the backend `ScryfallClient.GetArtVersionsAsync`, which logs a warning ("Scryfall has more results") when it hits the same cap, the frontend emits no signal at all and returns no `has_more`-style flag to the caller. The art grid and the AR reference-image set are both built from this list, so a printing beyond page 10 is simply invisible and can never be recognized or selected — with nothing to indicate the list was cut short.

This is upstream of, and distinct from, the known AR issue about the 12-oldest slice omitting the viewed printing: this is the truncation of the source list itself. Returning a `truncated`/`hasMore` flag (as the backend already knows internally) would let the UI at least indicate the list is incomplete.
