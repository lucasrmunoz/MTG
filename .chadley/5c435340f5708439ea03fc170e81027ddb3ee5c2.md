`fetchArtVersions` constructs the exact-name Scryfall query by directly interpolating the raw `name` into a quoted string:

```ts
const query = encodeURIComponent(`!"${name}"`);
```

The sibling search path, `buildNameQuery`, deliberately strips embedded quotes and backslashes per word:

```ts
.map((word) => word.replaceAll('"', "").replaceAll("\\", ""))
```

Because `fetchArtVersions` does not do this, a name containing a double quote or backslash (or a caller passing a not-yet-sanitized string) produces a malformed query such as `!"Urza"s"`. Scryfall returns 404, and the code's 404 handler treats that as "no printings" and returns `[]` — so the art-version grid silently shows nothing rather than the card's printings. The two lookup paths disagree on sanitization for the same user input.

Fix: run `name` through the same quote/backslash stripping (or reuse a shared sanitizer) before building the `!"..."` clause.
