When the user selects a non-default art version and taps **View in AR**, the floated image (`imageUrl`) correctly reflects the chosen printing, but the identifier handed to the native layer (`cardId`) is still `card.id` — the printing that search/random originally returned.

Since the AR screen keys its per-printing counters off `cardId`, the counters shown/persisted belong to the *default* printing, not the one whose art the user is looking at — a silent mismatch between the picture and its saved state.

**Fix:** pass the selected printing's id, e.g. resolve the `ArtVersion` matching `selectedArtUrl` and use `selectedVersion?.id ?? card.id` for `cardId` (the page already computes `previewVersion` this way for pricing).
