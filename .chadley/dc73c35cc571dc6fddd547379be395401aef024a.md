When the user picks a non-default art version, the main image switches to that printing (`selectedArtUrl`), but the `cardId` handed to the native AR bridge still points at the originally-searched printing:

```tsx
await cardAr.open({
  cardId: card.id,                       // always the originally-searched printing
  cardName: card.name,
  imageUrl: selectedArtUrl ?? card.imageUrl,  // reflects the SELECTED printing
  printings: artVersions.map((version) => ({ id: version.id, imageUrl: version.imageUrl })),
  keywords: card.keywords,
});
```

Each `ArtVersion` in `artVersions` carries its own printing `id`, so `selectedArtUrl` corresponds to a specific printing id that is never forwarded as `cardId`. The result is a mismatched `(cardId, imageUrl)` pair whenever a specific art version is selected: anything the AR layer keys on `cardId` (the 'current' printing highlight, telemetry, or the reference image chosen from `printings`) is associated with the wrong printing than the one on screen.

Fix: resolve the selected `ArtVersion` (via `selectedArtUrl`/`artVersions`) and pass its `id` as `cardId` when a specific printing is chosen, falling back to `card.id`.
