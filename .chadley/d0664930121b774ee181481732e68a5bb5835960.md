The known-issue list already flags the backend mapper (`ScryfallCardMapper.cs`) for accepting zero/negative TCGplayer prices while every other feed guards `> 0`. The browser-direct Scryfall client — the source of truth in GitHub Pages / no-API mode — has the **same defect independently**, and it lives in a different file so it is not covered by the backend fingerprint.

`parsePrice` returns any finite number, including `0` and negatives:

```ts
const parsed = Number.parseFloat(value);
return Number.isFinite(parsed) ? parsed : null;
```

Scryfall occasionally emits `usd: "0.00"` (tokens, oversized, broken listings). `tcgplayerPrices` then treats the card as *having* a price, because the null-check only fires when **both** finishes are null:

```ts
if (price.nonfoil === null && price.foil === null) { return {}; }
```

With `nonfoil === 0`, `priceFor` returns `0`, and `formatPrice` renders it as `$0.00` — indistinguishable from a real cheap listing rather than the intended "—" for "no known price."

**Fix:** mirror the vendor feeds' semantics with `return Number.isFinite(parsed) && parsed > 0 ? parsed : null;`.
