The custom starting-life input has no lower bound and mishandles an empty field:

```tsx
<input
  type="number"
  value={startingLife}
  onChange={(event) => {
    const value = Number(event.target.value);
    if (Number.isFinite(value)) {
      setStartingLife(Math.trunc(value));
    }
  }}
/>
```

Two problems:

1. **Cannot be cleared to retype.** `Number("")` is `0`, which is finite, so the moment the user deletes the field contents to type a new number it snaps to `0`. Editing the value is awkward — you effectively have to select-all and overwrite.
2. **No bounds.** Negative and zero values pass straight through to `createGame(playerCount, startingLife, layout)`, which seeds every player's `life` with them verbatim. "Start game" with `0` (or `-5`) starting life is fully reachable. While life is deliberately unclamped *during* play (Angel's Grace etc.), a *starting* total of 0 or negative is never a legitimate game.

A `min` (e.g. 1) plus tolerating an empty intermediate value (only committing on blur or when non-empty) would fix both.
