`LoadAsync` iterates `catalogue.Data ?? []`, so if the upstream returns an HTTP 200 whose JSON lacks a `data` array — e.g. an error envelope like `{"error":"..."}` served with 200, or `{"data":null}` — deserialization yields a `Response` with `Data == null`, the loop runs zero times, and the method returns an **empty** dictionary as a *successful* result.

`PriceRefreshService.RefreshAsync` then calls `cache.Set(feed.VendorId, prices)` unconditionally on success:

```csharp
var prices = await feed.LoadAsync(cancellationToken);
cache.Set(feed.VendorId, prices);
```

Because `PriceCache.Set` swaps the whole snapshot in (last-writer-wins), the previous good 149,000-row snapshot is replaced by an empty one, zeroing every Card Kingdom price in the app until the next *successful* hourly refresh. This directly contradicts the surrounding intent — `RefreshAsync`'s catch block comments "the previous snapshot stays in place" and `PriceCache` documents that only the previous or new catalogue is ever visible — but that guarantee only holds when `LoadAsync` throws, not when it returns an empty success.

Fix: treat a missing/null `data` (or a suspiciously-empty result relative to the previous snapshot) as a `PriceFeedException` so the keep-previous-snapshot path engages, rather than caching an empty catalogue as authoritative.
