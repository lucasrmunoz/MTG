The vendor-polling effect stops as soon as every vendor reports `loaded`:

```tsx
if (list.some((vendor) => !vendor.loaded)) {
  timer = setTimeout(() => void loadVendors(), VENDOR_POLL_MS);
}
```

Once Card Kingdom's first catalogue download completes, `loaded` is `true` and polling ceases permanently for the session. But `PriceRefreshService` keeps re-downloading the catalogue every hour and updates `fetchedAt` server-side, and `freshnessLabel` renders `as of ${minutes}m ago` from `Date.now() - fetchedAt`. Because the client never re-fetches `/api/vendors` after the first load (and nothing forces a re-render), a long-lived tab shows an ever-growing, increasingly wrong age — e.g. "as of 5h ago" moments after the backend actually refreshed. It's purely cosmetic, but the whole point of exposing `fetchedAt` is accurate staleness. Continuing to poll on a slow interval (or re-fetching vendors alongside searches) would keep the label honest.
