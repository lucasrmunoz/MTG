`getJson` unconditionally parses the success body as JSON:

```ts
if (!response.ok) {
  throw new ApiError(await readProblemDetail(response), response.status);
}
return (await response.json()) as T;
```

If a 2xx response has an empty body (e.g. a 204) or a non-JSON body (e.g. an HTML/plaintext page injected by an intermediary proxy that still returns 2xx), `response.json()` throws a raw `SyntaxError`. That error is not an `ApiError`, so callers that branch on `err instanceof ApiError` (e.g. CommanderPicker's catch, page error handling) fall through to a generic 'Something went wrong', losing the status and any diagnostic context. The error path (`readProblemDetail`) already guards its `response.json()` in try/catch; the success path does not.

Suggested fix: wrap the success-body parse in try/catch and rethrow as an `ApiError` (with the status), matching the error-path handling.
