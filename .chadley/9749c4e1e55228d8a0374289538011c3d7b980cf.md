The exception handler copies the internal exception message verbatim into the client-facing ProblemDetails:

```csharp
// src/Mtg.Api/ScryfallExceptionHandler.cs:35
Detail = exception.Message,
```

`ScryfallException.Message` embeds internal detail — e.g. `Scryfall returned {status} {ReasonPhrase} during {operation}` and `Could not reach Scryfall during {operation}. Check network connectivity.` (see `ScryfallClient.GetAsync`). The `{operation}` string includes the user's search term and an internal operation description, and the messages leak upstream status codes / network-topology hints into the 502 body sent to browsers.

The full exception is already logged server-side (`logger.LogError(exception, ...)`, line 24), so the client Detail can safely be a generic message (e.g. "The card data provider is temporarily unavailable") while the specifics stay in logs. Low severity — the leaked term is largely the caller's own input — but it is unnecessary information disclosure through an error surface.
