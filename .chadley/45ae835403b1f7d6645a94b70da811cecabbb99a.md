`AddFeed<TFeed>` registers the feed both as a typed `HttpClient` (transient) and as a **singleton** `IPriceFeed` whose factory resolves the typed client exactly once:

```csharp
private static void AddFeed<TFeed>(IServiceCollection services)
    where TFeed : class, IPriceFeed
{
    services.AddHttpClient<TFeed>(ConfigureVendorClient);
    services.AddSingleton<IPriceFeed>(provider => provider.GetRequiredService<TFeed>());
}
```

Because the outer registration is a singleton, `TFeed` (and the `HttpClient`/`HttpMessageHandler` injected into it) is resolved once and captured for the entire process lifetime. This is the classic "captured HttpClient" antipattern: `IHttpClientFactory`'s handler pooling/rotation never happens, so a DNS change for `api.cardkingdom.com` is never picked up. The `PriceRefreshService` (a `BackgroundService`/singleton) holds these `IPriceFeed` singletons and re-uses the same handler for every bulk pull, indefinitely.

This directly contradicts the intent stated a few lines above in `AddPricing`: the live sources are registered *scoped* precisely because they "are typed HTTP clients and must not be captured by a singleton" — yet `AddFeed` violates that rule.

**Fix:** don't capture a typed client in a singleton. Either make the feed transient/scoped and resolve it per refresh via a scope, or have `PriceRefreshService` create an `IServiceScope` per iteration and resolve `IEnumerable<IPriceFeed>` from it, so a fresh handler is used per pull.
