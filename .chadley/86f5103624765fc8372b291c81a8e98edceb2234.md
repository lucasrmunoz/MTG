`fetchRandomCard` is hard-wired to Scryfall in every mode:

```ts
// src/frontend/src/lib/api.ts:38
export const fetchRandomCard = scryfall.fetchRandomCard;
```

So a drawn card carries prices only under the `tcgplayer` key (see `tcgplayerPrices` in `scryfall.ts`). But in API mode the vendor dropdown is built from `VendorCatalog.List()`, which orders **live vendors first** and lists TCGplayer *last*:

```csharp
// src/Mtg.Core/Pricing/VendorCatalog.cs:21-49  → [manaPool, cardKingdom, tcgplayer]
```

and `page.tsx` defaults the selection to the first vendor:

```ts
// src/frontend/src/app/page.tsx:64
setVendorId((current) => (current === "" ? (list[0]?.id ?? "") : current));
```

so `vendorId` becomes `manaPool`. `priceFor(prices, "manaPool", finish)` returns `null` because the random card has no `manaPool` entry (`pricing.ts:26-29`), and `formatPrice` renders `"—"`. Meanwhile `CardDetail`/`PreviewPanel` still print `vendorLabel(vendor)` next to it, so every "Surprise Me" draw in a backend-enabled deployment shows `— Mana Pool (NM)` even though a real TCGplayer price exists on the object.

The result is actively misleading: it implies a specific vendor has no price for the card, when in fact that vendor was never consulted for random draws. Fix: when a random card is opened, reconcile the selected vendor to `tcgplayer` (the only vendor with data for that path), or add a random-card route to `Mtg.Api` so the enriched prices are populated.
