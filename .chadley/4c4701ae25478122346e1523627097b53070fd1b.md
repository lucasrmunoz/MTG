`freshnessLabel` computes the age of a cached (non-live) vendor's prices from `Date.now()` at render time:

```ts
const minutes = Math.floor(
  (Date.now() - new Date(vendor.fetchedAt).getTime()) / 60_000,
);
```

Nothing schedules a re-render as wall-clock time passes. The only recurring timer in the app is the vendor poll in `page.tsx`, and it **stops** once every vendor reports `loaded` (`if (list.some((vendor) => !vendor.loaded)) { timer = setTimeout(...) }`). After Card Kingdom finishes loading, no further state updates occur while the user sits idle, so a label rendered as "as of 2m ago" stays "2m ago" indefinitely and only corrects when some other interaction (search, hover, finish change) triggers a re-render.

Since this label exists specifically to convey how stale the cached prices are, a frozen value directly undermines its purpose.

**Fix:** drive an interval `setInterval`/`useEffect` tick (e.g. every 30–60s) in `PriceControls` to re-render the freshness labels, or compute an absolute timestamp tooltip that doesn't rely on continuous re-rendering.
