The decorative commander-art background uses a Next.js `fill` `Image` with no `sizes` prop:

```tsx
{player.commander?.artCropUrl != null && (
  <Image
    src={player.commander.artCropUrl}
    alt=""
    fill
    className="object-cover opacity-35"
  />
)}
```

A `fill` image without `sizes` defaults to `sizes="100vw"`, so Next selects the largest `srcSet` candidate (full viewport width) for what is actually a small, semi-transparent player-zone thumbnail — often several of them tiled on one screen. This wastes bandwidth and decode time on the game screen, which is exactly the mobile, possibly-offline context this app targets. (`alt=""` is correct — the image is decorative.)

Fix: add a `sizes` prop scoped to the zone's rendered width, e.g. `sizes="(max-width: 640px) 50vw, 25vw"`.
