A player's whole zone is two invisible half-width buttons over the card art:

```tsx
<button aria-label={`${player.name}: subtract life`} onPointerDown={() => startHold(-1)} ... />
<button aria-label={`${player.name}: add life`} onPointerDown={() => startHold(1)} ... />
```

The current life total and the running delta badge are rendered in a sibling that is explicitly non-interactive and carries no live-region semantics:

```tsx
<div className="pointer-events-none absolute inset-0 z-10 flex flex-col items-center justify-center">
  <span className="text-5xl ...">{player.life}</span>
  <span className={`... ${recent === 0 ? "invisible" : ""}`}>{recent > 0 ? `+${recent}` : recent}</span>
</div>
```

Consequences for a screen-reader / switch user:
- The two tap targets are labelled only "add life"/"subtract life"; activating them announces nothing about the resulting value, and there is no `aria-live` region, so tapping +1/−1 produces **no spoken feedback at all**. The user cannot tell whether their tap registered or what the total now is.
- The life number itself sits in a `pointer-events-none` span with no association to the buttons (no `aria-labelledby`, no live region), so it is reachable only via manual browse-mode exploration, not as feedback on the action they just took.

This is the core interaction of the game board (adjusting life), so the gap is worth closing even though it is a P3.

**Fix:** add an `aria-live="polite"` region that announces the player's new life after each change (e.g. a visually-hidden `"{player.name}: {player.life} life"` node updated on change), and/or reflect the current total in the buttons' accessible names (e.g. `aria-label={`${player.name}: subtract life, now ${player.life}`}`). A polite live region on the existing life `<span>` is the smallest change.
