`loadFromDisk` accepts a cache file after only a *type* check on `fetchedAt`:

```ts
if (typeof cache.fetchedAt !== "string" || typeof cache.prices !== "object") {
  throw new Error("The cache file does not have the expected shape.");
}
catalogue = new Map(Object.entries(cache.prices));
fetchedAt = cache.fetchedAt;
```

Staleness is then computed as:

```ts
function isStale(): boolean {
  return fetchedAt === null || Date.now() - new Date(fetchedAt).getTime() > MAX_AGE_MS;
}
```

If the persisted `fetchedAt` is a string that `Date` cannot parse (a corrupted-but-still-valid-JSON cache, or a shape change), `new Date(fetchedAt).getTime()` is `NaN`, and `Date.now() - NaN > MAX_AGE_MS` evaluates to `NaN > … === false`. So `isStale()` returns `false` **forever**: `ensureLoaded` sees a non-stale catalogue (`catalogue !== null && !isStale()`) and returns without ever re-downloading, and the 24h refresh trigger can never fire for the life of the process.

The same bad value flows to `getFetchedAt()` → the vendor's `fetchedAt`, where `freshnessLabel` renders `"as of NaNh ago"` (mirroring the already-known API-side NaN label bug, but here it is the *staleness gate itself* that breaks, not just the label).

Fix: after reading, validate the timestamp parses — e.g. treat `Number.isNaN(new Date(cache.fetchedAt).getTime())` the same as a corrupt cache (delete and re-download), or guard `isStale` to return `true` when the parsed time is `NaN`.
