`GetPricesAsync` is on the **live, per-request** price path (it runs while a user's `/api/cards/*` call is blocked). When a card has more than `MaxIdsPerRequest` printings it issues one HTTP request per chunk, but does so with an `await` inside a plain `foreach`, so each round trip is strictly serialized:

```csharp
foreach (var chunk in accepted.Chunk(MaxIdsPerRequest))
{
    var query = string.Join('&', chunk.Select(id => $"scryfall_ids={id:D}"));
    var response = await PriceFeedHttp.GetCatalogueAsync<Response>(
        httpClient, $"{Path}?{query}", DisplayName, cancellationToken);
    ...
}
```

Art-version lookups routinely return well over 100 printings, so a popular card pays 3+ *serial* network latencies inline in the request. The chunks are independent and their results are merged into a single dictionary, so they could be dispatched concurrently (e.g. `Task.WhenAll` over the chunks) to collapse the wall-clock cost to a single round trip.

This is distinct from the already-known shared-timeout issue — it compounds it: with a slow Mana Pool endpoint, the serial chunking multiplies the per-chunk latency by the number of chunks. Note any concurrency change must be considered alongside the known 'one failed chunk discards all prices' behavior.
