For a transform / modal double-faced card (e.g. *Delver of Secrets*, *Fable of the Mirror-Breaker*), the detail panel shows only the front art with no way to view the back face.

The back-face image is already fetched and wired all the way through: `toFace` in `scryfall.ts` sets `imageUrl: face.image_uris?.normal ?? null`, and `CardFace.imageUrl` is part of the type. But `CardDetail` renders only the top-level `card.imageUrl` and, per face, only name/type/oracle text — `face.imageUrl` is never read anywhere in the UI. The capability exists; the panel silently discards it.

Adding a flip control or a second image (using the already-present `face.imageUrl`) closes an obvious gap for a card class the app otherwise models. This is distinct from the known DFC item about aggregate power/toughness and per-face mana cost — this is specifically the unused back-face **image**, which no existing proposal covers.
