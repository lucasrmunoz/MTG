`showFoil` is derived purely from the finish selector, not from whether the printing actually has a foil price/finish:
```tsx
const showFoil = finish === "foil";
const price = priceFor(card.prices, vendorId, finish);
...
<CardImage ... foil={showFoil} ... />
...
<span className="...">{vendorLabel(vendor)}{showFoil ? " · foil" : ""}</span>
```
When the user sets the finish to **Foil** while viewing a card that was only printed nonfoil (its `finishes` do not include `foil`), `priceFor(..., "foil")` returns the missing foil price → `formatPrice` renders `"—"`, yet `CardImage` still applies the holographic sheen and the `✨ Foil` badge, and the price line is annotated `· foil`. The result is a plain card presented as a foil with a dash price.

This is the CardDetail counterpart of the already-tracked PreviewPanel behavior; it lives in a separate component/code path. It should gate the foil styling and the `· foil` label on the printing actually offering a foil finish (e.g. `card.finishes.includes("foil")`), as `matchesFinish` already models for the grid.
