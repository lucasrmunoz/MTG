The browser/native-direct Scryfall path and the C# `ScryfallClient` are meant to return the same results for the same query, but their secondary sort keys differ. When two cards tie on `matchRank`, the frontend breaks the tie with `String.prototype.localeCompare` (locale-sensitive, case-sensitive collation), while the server breaks it with `StringComparer.OrdinalIgnoreCase`. For names differing only in case or containing locale-collated characters (accents, ligatures like `Æ`), the two code paths order results differently for the identical query — a user sees a different result order in native/web-direct mode than in API mode.

**Fix:** Use a matching comparison in the frontend, e.g. an ordinal case-insensitive compare or `localeCompare(right.name, undefined, { sensitivity: "base" })`, so both paths order identically.
