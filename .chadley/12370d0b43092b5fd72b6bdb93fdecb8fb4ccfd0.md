CORS origins fall back to a hard-coded localhost value when configuration is missing:

```csharp
// src/Mtg.Api/Program.cs:9-10
var allowedOrigins = builder.Configuration.GetSection("Cors:AllowedOrigins").Get<string[]>()
                     ?? ["http://localhost:3000"];
```

In a production deployment where `Cors:AllowedOrigins` is not configured, the API silently accepts only `http://localhost:3000`, so the real deployed frontend is blocked by CORS. Because there is no fail-fast, this misconfiguration surfaces as an opaque browser CORS failure rather than a clear startup error. Consider failing fast (or logging a prominent warning) when `Cors:AllowedOrigins` is unset outside the Development environment, instead of masking a missing-config deployment with a localhost default.
