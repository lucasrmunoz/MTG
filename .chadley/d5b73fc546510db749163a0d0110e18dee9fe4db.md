`parseTurnState` receives the parsed `players` array and uses it to validate `activePlayerId` (falling back to seat 1 when the id owns no seat, game.ts:398-401), but `parseReminder` only checks `typeof playerId === "number"` and never validates `playerId` against the player list. A restored save whose reminder references a seat that does not exist in `players` (a shorter player roster, a hand-edited or format-migrated save) is loaded intact.

Effect: the orphaned reminder is invisible on the board — each `PlayerZone` filters reminders with `reminder.playerId === player.id`, so no zone ever renders it — yet it lives in game state, is re-serialized on every save forever, bumps `nextReminderId` via `highestId`, and can never come due or be dismissed. It is permanent, unreachable, undismissable state.

Suggested fix: in `parseTurnState`, drop reminders whose `playerId` matches no entry in `players`, the same way `activePlayerId` is reconciled.
