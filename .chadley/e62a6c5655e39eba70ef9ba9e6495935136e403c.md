`startingLife` — a top-level `GameState` field distinct from per-player `Player.life` — is validated only with a loose type check and then passed straight into the returned state:

```ts
const { startingLife, layout, players } = envelope.game;
if (
  typeof startingLife !== "number" ||   // line 341
  ...
) {
  return null;
}
...
return { startingLife, layout, players: parsedPlayers, ...turnState };  // line 363
```

`typeof startingLife !== "number"` passes `NaN`, `Infinity`, negative values, and fractional values. This is a separate, weaker check than the per-player guard in `parsePlayer`, so it is not covered by the known "restored saves accept non-finite life/commanderCasts" item. A corrupt `startingLife` propagates into any UI that displays the starting total, and since `createGame` also spreads `startingLife` to each seat, any "reset to starting life" path would poison every player's life with the bad value.

**Fix direction:** Require `Number.isFinite(startingLife)` and a positive integer (mirroring the `Math.trunc`/`Math.max` clamps used elsewhere), rejecting or clamping otherwise.
