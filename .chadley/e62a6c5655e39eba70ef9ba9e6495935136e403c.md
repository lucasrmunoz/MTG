`parsePlayer` validates each player's fields but nothing checks that player `id`s are **unique** across the restored roster:

```ts
for (const entry of players) {
  const player = parsePlayer(entry);
  if (player === null) return null;
  parsedPlayers.push(player);
}
```

Player `id` is the identity used everywhere for mutation and turn tracking. With two players sharing an id, several helpers misbehave:

- `updatePlayer` (and thus `adjustLife`, `adjustCommanderCasts`, `setPlayerName`, `setCommander`) updates **every** player whose `id` matches, so a life change to one seat changes both duplicated seats.
- `endTurn` advances via `findIndex(player => player.id === activePlayerId)`, which always returns the **first** match; ending the second duplicate's turn jumps back to the first, so the marker can never leave the first duplicate — rotation stalls.
- `applyArPlayers` merges AR results into all matching ids at once.

The storage envelope is deliberately versioned and validated to "discard old saves instead of crashing on them," and the file already rejects out-of-range player counts and bad turn ids — a uniqueness check belongs in the same guard. This is reachable from any hand-edited or corrupted `localStorage` save ("mtg.game.v1").

Fix: after parsing players, return `null` (reject the save) when `new Set(players.map(p => p.id)).size !== players.length`.
