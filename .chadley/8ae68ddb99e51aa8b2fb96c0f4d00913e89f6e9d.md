`parseReminder` validates that each reminder's `id` is a number but never checks that ids are unique across the reminder array. A corrupted or hand-edited save with two reminders sharing an `id` is accepted verbatim. This is distinct from the already-known *duplicate player ids* item — reminders have their own downstream consequences:

1. **Dismissal removes the wrong reminder(s).** `dismissReminder` filters by `reminder.id !== reminderId`, so dismissing one of the duplicates silently deletes *both* — the user loses an unrelated pending reminder they never touched.
2. **Duplicate React keys.** `PlayerZone`/reminder rows render with `key={reminder.id}`, so duplicate ids produce unstable, warning-generating rendering.

Note `nextReminderId` is set to `Math.max(..., highestId + 1)` on restore, so newly-added reminders won't collide — but the pre-existing duplicates persist.

**Fix:** In `parseTurnState`, drop later duplicates (or reject the save) when `parsedReminders` contains repeated ids, mirroring the duplicate-player-id handling.
