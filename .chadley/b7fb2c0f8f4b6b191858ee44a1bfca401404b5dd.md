`GetCatalogueAsync` streams and deserializes the vendor catalogue with no bound on the number of bytes read:

```csharp
// src/Mtg.Core/Pricing/PriceFeedHttp.cs:30
response = await httpClient.GetAsync(url, HttpCompletionOption.ResponseHeadersRead, cancellationToken);
...
// line 51
return await response.Content.ReadFromJsonAsync<T>(cancellationToken) ...
```

The remarks note the document is ~66 MB and relies on System.Text.Json skipping unmapped fields to bound *object* allocation — but nothing caps the raw stream. `HttpCompletionOption.ResponseHeadersRead` means bytes are consumed lazily during deserialization with no `MaxResponseContentBufferSize` and no `Content-Length` sanity check. These feeds are explicitly "undocumented, unsupported" third parties (per `CardKingdomFeed`), and the price HttpClient uses a 10-minute timeout, so a compromised or misbehaving endpoint could stream an unbounded body and exhaust CPU/memory over a long window. Add a size cap (reject when `Content-Length` exceeds a sane maximum, or wrap the content stream in a byte-limited reader) before deserializing.
