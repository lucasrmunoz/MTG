`FetchLiveAsync` collects results from every registered `ILivePriceSource` and materializes them with `ToDictionary` keyed on `VendorId`:

```csharp
return results.ToDictionary(result => result.VendorId, result => result.Prices);
```

`ToDictionary` throws `ArgumentException` on a duplicate key. The service is explicitly built to enumerate `IEnumerable<ILivePriceSource>`, and its own remarks state "a vendor being down must not fail the card lookup." But if a second live source is ever registered that (accidentally) reuses a `Vendors` constant as its `VendorId`, every card and art-version lookup throws an unhandled exception — a hard 500 — rather than degrading. The per-source try/catch protects against a vendor being *down*, but not against a duplicate id at aggregation time.

With only one live source today this cannot fire, but it is a latent fragility directly at odds with the stated resilience goal. Fix: use a last-wins/`GroupBy` merge instead of `ToDictionary`.
