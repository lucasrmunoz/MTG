The two large life-adjust hit areas are `<button>` elements wired up with **only** pointer handlers (`onPointerDown`, `onPointerUp`, `onPointerLeave`, `onPointerCancel`). There is no `onClick` and no `onKeyDown`. A keyboard or switch-access user who tabs to the "subtract life" / "add life" button and presses Enter or Space fires a synthetic `click` event that nothing listens for, so **life cannot be changed at all without a pointer**. Because these buttons render no visible text (life is shown in a separate `pointer-events-none` overlay), they also present as focusable controls that appear to do nothing.

**Fix:** add an `onClick` (or `onKeyDown` for Enter/Space) that performs a single `startHold`/`step`-equivalent increment/decrement, so keyboard activation changes life once even though press-and-hold repeat remains pointer-only. Ensure the single-step keyboard path does not also start the hold-repeat interval.
