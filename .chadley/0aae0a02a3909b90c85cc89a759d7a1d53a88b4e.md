`handleSelect` sets `picking` to `true` up front, but its stale-request guard returns early **without** clearing it:

```ts
// src/frontend/src/components/CommanderPicker.tsx
async function handleSelect(card: Card) {
  const requestId = ++requestIdRef.current;
  setPicking(true);

  let artCropUrl: string | null = null;
  try {
    const versions = await fetchArtVersions(card.name);
    const version = versions.find((entry) => entry.id === card.id) ?? versions[0];
    artCropUrl = version?.artCropUrl ?? null;
  } catch { /* decoration only */ }

  if (requestId !== requestIdRef.current) {
    return;                 // <-- early return, setPicking(false) never runs
  }
  setPicking(false);
  onPick({ id: card.id, name: card.name, imageUrl: card.imageUrl, artCropUrl });
}
```

Every `handleSearch` also bumps `requestIdRef.current`. So if the user selects a card (or a single-match auto-selects) and then submits another search while `fetchArtVersions` is still in flight, the in-flight `handleSelect` sees `requestId !== requestIdRef.current` and returns, leaving `picking === true` forever.

The search form is driven by that flag:

```tsx
<SearchForm value={query} loading={loading || picking} ... />
```

and `SearchForm` disables its submit button whenever `loading` is true. The result: the search button is stuck showing the spinner and cannot be pressed again until the user closes and reopens the picker. (Clicking a result card still calls `handleSelect`, which recovers, but the primary search input is dead in the meantime.)

Fix: reset `picking` in a `finally`, or only skip the `onPick`/state updates — not the `setPicking(false)` — on a stale request.
