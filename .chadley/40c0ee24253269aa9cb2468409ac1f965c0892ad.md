`GetCatalogueAsync` is documented as "turning every failure into `PriceFeedException` so the refresh loop has one thing to catch." It downloads with `HttpCompletionOption.ResponseHeadersRead`, so the response body is **not** buffered during `GetAsync` — it is streamed later, during `ReadFromJsonAsync`.

The outer `try` around `GetAsync` catches `TaskCanceledException` (a timeout) and rewraps it (lines 36-39). But the inner `try` around the streaming deserialization only catches `JsonException`:

```csharp
try
{
    return await response.Content.ReadFromJsonAsync<T>(cancellationToken)
           ?? throw new PriceFeedException($"The {vendorName} price feed returned an empty body.");
}
catch (JsonException ex)
{
    throw new PriceFeedException($"Could not parse the {vendorName} price feed.", ex);
}
```

`HttpClient.Timeout` applies to the *entire* operation, including reading the streamed body. If the ~66 MB feed stalls or times out mid-stream, `ReadFromJsonAsync` throws `TaskCanceledException`, which is not caught here and propagates as a raw `TaskCanceledException` — precisely the failure mode the method claims to eliminate. Callers such as `CardKingdomFeed.LoadAsync` and `ManaPoolLiveSource.GetPricesAsync` (which only expect `PriceFeedException`) then see an unwrapped cancellation exception, and a refresh loop that catches `PriceFeedException` will miss it.

**Fix:** mirror the outer handler on the inner `try`:

```csharp
catch (TaskCanceledException ex) when (!cancellationToken.IsCancellationRequested)
{
    throw new PriceFeedException($"The {vendorName} price feed timed out.", ex);
}
```
