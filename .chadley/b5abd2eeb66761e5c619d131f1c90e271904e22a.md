`is_foil` arrives as the quoted string `"true"`/`"false"` (per the record's own doc comment), but the merge only tests for `"true"` and sends everything else down the nonfoil branch:

```csharp
var isFoil = string.Equals(row.IsFoil, "true", StringComparison.OrdinalIgnoreCase);
prices.TryGetValue(id, out var existing);
prices[id] = isFoil
    ? new VendorPrice { Nonfoil = existing?.Nonfoil, Foil = nearMint }
    : new VendorPrice { Nonfoil = nearMint, Foil = existing?.Foil };
```

Since the feed publishes foil and nonfoil as separate rows sharing one `scryfall_id`, any row whose `is_foil` is `null` or an unexpected value (this is explicitly an undocumented, unstable feed) is written into the **Nonfoil** slot. If a genuine nonfoil row for the same id was already parsed, the malformed row overwrites its price. The `scryfall_id` path already skips-and-counts unparseable rows; the finish path silently mis-buckets them instead.

Suggested fix: parse `is_foil` explicitly and skip (or log) any row whose finish is neither `"true"` nor `"false"`, rather than defaulting unknown finishes to nonfoil.
