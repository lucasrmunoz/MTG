For a card with more than 100 printings (a long art-version list), `fetchPrices` splits the ids into 100-id chunks. A single chunk failing — a transient 5xx, a 400 from one malformed id that slipped past the regex, or a dropped connection — throws out of `fetchPrices` entirely, discarding every price already collected from earlier successful chunks.

`nativeApp.enrich` catches that throw and falls back to an empty map, so the user sees Mana Pool dashes for the *entire* result even though most chunks succeeded.

This is the frontend/native-app twin of the already-tracked C# `ManaPoolLiveSource` issue; it lives in a separate code path (`manaPool.ts`, used only in `NEXT_PUBLIC_MOBILE_APP=true` builds) and needs its own fix.

**Fix:** collect chunk results into the shared map and let a failed chunk skip only its own ids (try/catch per chunk, or `Promise.allSettled`), so successful chunks still contribute prices.
