The API runs a background `PriceRefreshService` that fills `PriceCache` over tens of seconds after startup, and `PriceCache` already exposes an `IsLoaded` signal — but there is no health/readiness endpoint. `AddHealthChecks`/`MapHealthChecks` are never called, and no other endpoint surfaces load state. In a container/orchestrator deployment a liveness/readiness probe has nothing to hit, so the platform cannot distinguish "process up but the Card Kingdom feed is still downloading" from "ready," nor detect a wedged process.

**Fix:** add `builder.Services.AddHealthChecks()` and `app.MapHealthChecks("/health")`, optionally with a readiness check reporting `PriceCache.IsLoaded(Vendors.CardKingdom)` so orchestrators can gate traffic (or surface feed staleness) instead of treating a half-warmed instance as fully ready.
